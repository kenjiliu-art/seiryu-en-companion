# JACCC Content Framework

Version 1.0

## Purpose

This document defines the kinds of cultural heritage objects that may be represented across JACCC's future digital projects.

It is intentionally independent of any particular website, database, or software platform.

Its purpose is to create a shared language that allows future projects to work together while remaining flexible enough to evolve over time.

---

# Core Principle

Digital projects should represent real things.

Software exists to describe relationships between those things.

---

# Core Object Types

## Place

Examples

- Seiryū-en
- Upper Waterfall
- James Irvine Japanese Garden
- Little Tokyo
- George J. Doizaki Gallery

A Place may contain other Places.

A Place may contain Features.

A Place may be associated with Events, Works, People, and Collections.

---

## Feature

Examples

- Stream
- Bridge
- Lantern
- Stone arrangement
- Water basin
- Garden path

Features exist within Places.

---

## Living Thing

Examples

- Japanese Maple
- Black Pine
- Moss
- Koi
- Bird species

Living Things may belong to Places and may relate to Works, Seasons, and Features.

---

## Person

Examples

- Takeo Uesugi
- Morio Hayashida
- Tokio Ueyama
- Gardeners
- Artists
- Poets

---

## Work

Examples

- Painting
- Poem
- Book
- Mural
- Exhibition
- Musical composition

---

## Event

Examples

- Garden construction
- Exhibition
- Performance
- Volunteer day
- Conservation project

---

## Media

Examples

- Photograph
- Audio recording
- Video
- Illustration
- Scan

Media documents something else.

Media is not the primary object.

## Document

Examples

# Editorial Principle

The framework should describe documented relationships.

Relationships should not be invented.

Whenever practical, relationships should be supported by sources.

---

# Long-Term Goal

Future JACCC projects should share this conceptual framework even if they use different software platforms.

The framework should outlast any individual website, CMS, or database.
